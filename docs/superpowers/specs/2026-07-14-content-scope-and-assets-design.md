# 内容目录范围与 Obsidian 附件设计

## 1. 目标

InkHub 将 Obsidian Vault 作为配置和资源安全边界，但只管理用户明确选择的 Markdown 目录。目录规则适合 PARA 等知识管理结构，默认保护私人笔记，并能正确预览已纳入文章引用的 Vault 内图片。

## 2. 核心概念

- **Vault 根目录**：校验 `.obsidian`、解析 Obsidian 配置和限制本地资源访问的边界。
- **内容目录**：用户明确授权 InkHub 递归管理的 Vault 相对目录，可以有多个。
- **忽略目录**：内容目录内部不由 InkHub 管理的 Vault 相对目录，可以有多个。
- **附件**：被已纳入文章引用的非 Markdown 资源。附件不受内容目录限制，但必须位于 Vault 内。

目录规则只决定文章是否由 InkHub 管理，不决定文章是否发布到 Hugo 或微信。

## 3. 目录规则

一篇 Markdown 被纳入，当且仅当：

1. 文件位于至少一个内容目录中；
2. 文件不位于任何忽略目录中；
3. 文件不位于系统永久忽略目录中。

规则固定为：

- 内容目录递归包含所有子目录。
- 忽略目录永远优先，不支持在忽略目录中再次纳入。
- 忽略目录必须是某个内容目录本身或其后代；选择内容目录本身作为忽略目录没有意义，应拒绝。
- 选择父内容目录后移除冗余的子内容目录。
- 路径统一清理为使用 `/` 的 Vault 相对路径，拒绝绝对路径、空路径、`.`、`..` 和越界路径。
- `.obsidian`、`.git`、`.trash` 和以 `.inkhub-` 开头的目录永久忽略，不成为用户配置。
- 没有内容目录时不扫描任何 Markdown，不将“整个 Vault”作为隐式默认值。
- MVP 不支持 glob、正则、单文件规则、frontmatter 纳入标记、排除后重新纳入或渠道专属目录规则。

配置示例：

```yaml
content_roots:
  - Areas
  - Projects/OpenSource
ignored_folders:
  - Areas/私人记录
  - Areas/每日记录
```

配置保存到 `sources.config_json`，只保存 Vault 相对路径。配置变化使扫描 cursor 失效，并触发一次全量重扫。

## 4. 初始化与设置交互

选择 Vault 后，InkHub 展示包含 Markdown 数量的一级目录，但默认不勾选。用户可以：

1. 添加一个或多个“管理这些目录”；
2. 按需添加“其中不管理这些目录”；
3. 查看预计纳入文章数量；
4. 确认后创建工作区。

设置页允许修改相同规则。保存前展示“将新增 N 篇、移出 N 篇”；确认后重扫。移出范围只将索引记录标记为删除，不删除或修改 Markdown 文件。重新纳入时恢复同一索引记录。

## 5. Markdown 兼容与身份

- 有合法 frontmatter 的文章读取标准字段。
- 没有 frontmatter 的普通 Markdown 仍进入内容库，标题回退为不带扩展名的文件名，并标记元数据不完整。
- 空标题同样回退为文件名，回退值只用于索引和展示，不自动写回源文件。
- 常见的单字符串 `tags` 规范化为单元素数组。
- YAML frontmatter 已声明但语法损坏时不得静默忽略，记录为扫描失败。
- `stable_id` 只在非空时要求工作区内唯一。无稳定 ID 的文章使用 `source_id + relative_path` 生成内部 `ArticleID`。
- 首次受控元数据写回时可以生成稳定 ID；扫描本身不批量修改用户文件。

数据库迁移必须将现有 `UNIQUE(stable_id, workspace_id)` 改为仅约束非空稳定 ID的部分唯一索引，并保留路径唯一约束。

## 6. 已有工作区恢复

应用启动后为最近工作区执行可恢复的全量扫描，或者在已有扫描任务完成后根据配置版本判断是否需要重扫。首版采用启动时重扫最近工作区，保证迁移后的现有数据库自动补齐文章，不要求用户删除数据库。

扫描报告必须保留 `indexed` 和 `failed` 数量。单篇失败不能中止其他文章，错误不得包含文章正文。

## 7. Obsidian 附件解析

支持：

```markdown
![[image.png]]
![[image.png|640]]
![](assets/image.png)
![](../attachments/image.png)
```

解析规则：

- 读取 `.obsidian/app.json` 的 `attachmentFolderPath`、`newLinkFormat` 和 `useMarkdownLinks`，并将附件目录规范化为 Vault 根目录、当前文章目录、当前文章子目录或指定 Vault 相对目录四种语义。
- Markdown 相对路径首先相对当前文章目录解析；以 `/` 开头的 Markdown 路径解释为 Vault 根目录相对路径，不解释为本机绝对路径。
- Obsidian Wiki 嵌入按 `./`、`../` 当前文章相对路径、Vault 根目录路径或附件设置解析；无目录的短名称按最短且唯一规则解析。同名歧义时返回可理解的检查错误。
- `newLinkFormat` 只决定未来生成链接的偏好，读取已有文章时三种链接形式全部兼容；`useMarkdownLinks` 用于展示和发布转换诊断，不限制已有语法。
- `.obsidian/app.json` 的内容指纹参与扫描修订，附件配置变化会触发重扫和资源重新解析。
- `http` 和 `https` 图片保留为远程 URL，不由后端代理。
- 其他协议、绝对本地路径、Vault 外相对路径和符号链接逃逸全部拒绝。

图片资源解析失败只记录为资源诊断，不阻塞文章 frontmatter、内容阶段和文章索引；Hugo 或微信发布前检查将资源诊断提升为阻断问题。

附件可以位于未纳入的目录中，但只有被已纳入文章引用时才允许读取。未引用附件不建立文章索引，也不自动发布。

## 8. 安全资源接口

文章预览不得包含本机绝对路径。后端提供文章级资源地址：

```text
GET /api/v1/articles/{article_id}/assets/{asset_token}
```

`asset_token` 绑定文章、规范化引用路径和当前源文件指纹，不能作为任意文件路径使用。请求处理必须重新确认：

- 文章属于当前工作区和 Source；
- 资源引用来自该文章；
- 真实路径位于 Vault 根目录内；
- 符号链接解析后仍位于 Vault 内；
- 文件 MIME 类型属于允许的预览图片类型。

响应设置明确的 `Content-Type`、`X-Content-Type-Options: nosniff` 和本地缓存策略。SVG 首版不以内联方式展示，避免脚本内容进入文章 DOM。

## 9. 发布边界

文章预览、Hugo 资源复制和微信图片托管是三个独立能力。本阶段只保证本地文章预览：

- Hugo 后续将本地附件复制到站点资源目录并重写 URL。
- 微信后续依赖图片托管或人工上传。
- 本地预览成功不得将渠道状态标记为已发布或已准备。

## 10. 测试与验收

- 目录规则覆盖多内容目录、递归、忽略优先、冗余合并、越界和系统目录。
- 数据库迁移允许同工作区多篇空稳定 ID文章，并继续拒绝重复的非空稳定 ID。
- 已有工作区启动重扫后补齐文章，不重复创建索引。
- 无 frontmatter 和空标题文章使用文件名展示；损坏 YAML 计入失败。
- Markdown 图片、Wiki 嵌入、Obsidian 附件目录、远程 URL、同名歧义和越界路径均有测试。
- HTTP 资源接口覆盖合法图片、未引用资源、其他文章 token、符号链接逃逸和 MIME 限制。
- 前端覆盖初始化目录配置、规则摘要、文章图片渲染、空状态和错误状态。
- 完成后执行 Go 全量测试、竞态检查、vet、前端测试、lint、类型检查、生产构建和关键浏览器流程。
