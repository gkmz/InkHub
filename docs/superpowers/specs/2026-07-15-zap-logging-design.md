# Zap 结构化日志设计

## 目标

为 InkHub 增加可运维的结构化日志能力。日志参数从项目根目录 `.env` 和进程环境变量读取，进程环境变量优先；仓库提供 `.env.example`，真实 `.env` 不提交。

## 配置

支持以下变量：

- `INKHUB_LOG_LEVEL`：`debug`、`info`、`warn`、`error`，默认 `info`。
- `INKHUB_LOG_FILE`：日志文件路径；为空时使用 `<data-dir>/logs/inkhub.log`。
- `INKHUB_LOG_MAX_SIZE`：单个日志文件最大 MiB，默认 `100`，必须大于 0。
- `INKHUB_LOG_CONSOLE`：是否同时输出到控制台，默认 `true`。

轮转固定保留 5 个文件、30 天并压缩，先避免增加不必要配置。文件采用 JSON 编码，控制台采用便于本地阅读的编码。

## 代码边界

`internal/platform/logging` 定义配置、校验、Zap 构造和同步关闭，不依赖业务代码。`internal/app/bootstrap` 加载 `.env`、合并环境变量、初始化日志，并向 HTTP 服务传入 logger。HTTP 中间件生成或沿用合法的 `X-Request-ID`，记录方法、路由、状态码、响应大小和耗时。

启动路径记录配置摘要、数据库打开结果、工作区重扫结果、任务恢复与服务监听/退出。业务标识仅使用稳定 ID。日志不得记录正文、请求体、响应体、Secret、AI 完整请求、微信 HTML 和用户文件绝对路径。

## 错误处理

配置值非法、日志目录无法创建或日志文件无法打开时，启动立即失败并输出可理解错误。日志同步在退出时执行；标准输出和标准错误可能返回不可处理的同步错误，此类错误不覆盖应用原始退出结果。

## 测试与验收

单元测试覆盖默认值、环境变量覆盖、非法级别/大小/布尔值、JSON 文件输出和轮转参数。HTTP 测试覆盖 request ID、状态码与耗时字段，并确认不记录查询参数和请求体。完成后运行 `go test ./...`、`go test -race ./...`、`go vet ./...`，并复查 `.env` 未被纳入提交。
