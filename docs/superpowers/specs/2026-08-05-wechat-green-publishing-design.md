# 微信墨绿模板与发布准备设计

## 目标

恢复旧版微信发布体验，并保证页面预览、复制内容和粘贴到微信公众号后的结果一致：

- 仅保留旧版墨绿色微信模板，并将它作为默认模板。
- 将模板和 Mermaid 样式设置放到页面下方的内容操作区。
- 将文章链接转换为正文编号和文末“引用链接”章节。
- 恢复 Mermaid 的“手绘”和“现代”样式，默认使用手绘样式。
- 修复 Mermaid 代码块未渲染、直接显示源代码的问题。

## 交互设计

微信页面顶部不再显示模板选择。内容操作区在“准备微信内容”之前显示本次准备设置：

- 排版模板：显示唯一的“墨绿模板”。交互结构继续使用模板字段，便于以后新增模板，但当前没有其他选项。
- Mermaid 样式：使用“手绘 / 现代”分段选择，默认手绘，仅对当前文章本次准备生效。

准备完成后，页面继续显示预览、复制到微信和重新准备操作。用户修改 Mermaid 样式后，需要重新准备内容，复制结果始终来自最新准备版本。

## 渲染设计

### 墨绿色模板

模板样式以历史 `old` 实现为准，恢复绿色强调色、标题标记、引用块、代码块、表格和正文排版。内置模板注册表仅保留这一项，并作为微信提供方的默认模板。

### 链接引用

链接引用在后端微信 HTML 渲染过程中生成，确保复制出的 HTML 已包含完整引用。转换规则如下：

- 普通外部链接后追加连续编号。
- 文末追加“引用链接”章节，列出编号、链接文字和 URL。
- 空链接、页内锚点、`javascript:`、图片链接以及代码块内链接不转换。
- 引用节点在 HTML 清理前写入内联样式，避免微信公众号复制流程丢失样式。

### Mermaid

准备请求携带本次选择的 Mermaid 样式，并将它写入签名计划和发布任务数据，避免预览与异步准备结果不一致。后端 Mermaid 图片请求使用对应主题配置；前端预览也使用同一选择。

Mermaid 围栏识别兼容大小写、LF/CRLF、可选尾部换行及常见空白。渲染失败时页面显示明确错误，不再静默保留 Mermaid 源代码。

## 数据流

1. 页面选择 Mermaid 样式并请求生成微信准备计划。
2. 后端校验模板和 Mermaid 样式，将二者纳入计划签名及任务标识。
3. 用户确认准备后，任务携带固定的模板与 Mermaid 样式执行。
4. 渲染器处理 Markdown、Mermaid 图片、链接引用和模板内联样式。
5. 页面预览并复制该准备结果，保证所见即所得。

## 异常与兼容

- 未传 Mermaid 样式时使用 `handdrawn`，兼容旧请求和已有调用方。
- 未识别的 Mermaid 样式在计划阶段返回可理解的参数错误。
- Mermaid 远程图片生成失败时保留明确失败状态，允许用户修改内容后重新准备。
- 删除旧模板后，历史配置中的模板标识自动回退到唯一的墨绿模板，避免工作区无法启动。

## 验证范围

本次不新增自动化测试代码。实现完成后运行项目现有的前端类型检查、构建和后端现有测试，并启动本地页面供用户完成以下验收：

- 模板设置位于内容操作区，且只有墨绿模板。
- 手绘和现代 Mermaid 均能生成图表，不显示源代码。
- 普通链接带编号，文末存在“引用链接”章节。
- 点击复制成功，粘贴到微信公众号编辑器后保留预期样式。
