# InkHub 数据目录环境配置设计

## 1. 背景

InkHub 默认将 SQLite、日志、备份和发布暂存文件保存在操作系统应用数据目录。macOS 下默认目录为 `~/Library/Application Support/InkHub`。该位置适合正式产品，但用户无法从项目配置中直接确认实际数据目录。

本设计允许用户在项目根目录 `.env` 中显式配置数据目录，同时保留操作系统默认值和命令行临时覆盖能力。

## 2. 目标与非目标

### 2.1 目标

- 支持通过 `INKHUB_DATA_DIR` 配置 InkHub 数据目录。
- 在 `.env.example` 和 README 中说明目录用途、默认值和配置优先级。
- 保留现有 `--data-dir` 参数，并让命令行显式参数拥有最高优先级。
- 拒绝不明确的相对路径，避免从不同工作目录启动时打开不同数据库。
- 启动日志记录最终数据目录和配置来源，方便用户诊断。
- 未配置环境变量时保持现有行为，不迁移或复制已有数据库。

### 2.2 非目标

- 不把数据目录写入 SQLite。程序必须先确定目录，才能打开数据库。
- 不自动移动已有数据库、日志、备份或暂存文件。
- 不新增 YAML、TOML 等第二套配置文件。
- 不在设置页面实现数据目录迁移功能。

## 3. 配置格式

`.env.example` 增加：

```dotenv
# InkHub 数据目录，包含 SQLite、日志、备份和发布暂存文件；必须使用绝对路径
# macOS 示例：/Users/your-name/Library/Application Support/InkHub
INKHUB_DATA_DIR=
```

空值等同于未配置。非空值必须是清理后的绝对路径。环境变量值不展开 `~`，避免 shell、dotenv 和不同操作系统产生不一致语义；文档示例使用完整绝对路径。

## 4. 配置优先级

启动配置按以下顺序从低到高合并：

1. 操作系统默认目录：`os.UserConfigDir()/InkHub`。
2. `.env` 或进程环境中的 `INKHUB_DATA_DIR`。
3. 命令行显式传入的 `--data-dir`。

只有用户实际传入 `--data-dir` 时才覆盖环境变量。`flag` 包生成的默认值不能被误判为显式命令行配置。

现有 `Config`、`Layer` 和 `MergeConfig` 继续作为配置合并边界；启动解析负责构造默认层、环境层和命令行层，不让业务模块直接读取环境变量。

## 5. 校验与错误反馈

- `INKHUB_DATA_DIR` 非空但不是绝对路径时，启动失败并提示：`INKHUB_DATA_DIR 必须使用绝对路径`。
- `--data-dir` 非空但不是绝对路径时采用相同约束和明确错误。
- 目录不存在时沿用现有行为，以 `0700` 权限创建。
- 目录不可创建、不可写或实例锁冲突时沿用现有错误边界，不回退到其他目录，防止用户误以为正在使用指定数据库。
- 日志初始化后记录清理后的最终目录和来源：`default`、`environment` 或 `cli`。

日志只记录数据目录，不读取或记录 GitHub Token、AI Key 等 Secret。

## 6. 兼容性

- 未设置 `INKHUB_DATA_DIR` 且未传 `--data-dir` 时，继续使用现有系统目录，已有用户无行为变化。
- 设置新目录后，InkHub 将其视为独立数据目录；若其中没有数据库，则按首次启动创建新数据库。
- InkHub 不静默搬迁旧数据。需要迁移时，用户必须先停止服务，再显式复制完整数据目录或使用后续备份恢复能力。
- 日志文件未单独配置时，继续使用最终 `<data-dir>/logs/inkhub.log`。

## 7. 测试与验收

后端测试至少覆盖：

- 无环境变量和命令行参数时使用系统默认目录。
- `INKHUB_DATA_DIR` 覆盖默认目录。
- 显式 `--data-dir` 覆盖环境变量。
- 未显式传入 `--data-dir` 时，flag 默认值不覆盖环境变量。
- 空环境变量等同未配置。
- 环境变量相对路径和命令行相对路径均被拒绝。
- 绝对路径经过 `filepath.Clean` 后进入最终配置。
- 日志配置继续以合并后的数据目录计算默认日志文件路径。

人工验收：

1. 在 `.env` 配置一个新的绝对目录并启动 InkHub。
2. 确认该目录生成 `inkhub.db`、锁文件和日志目录。
3. 确认启动日志显示数据目录来源为环境配置。
4. 使用 `--data-dir` 指定另一个绝对目录，确认命令行覆盖生效。
5. 删除配置后重新启动，确认回到操作系统默认目录且不会自动迁移数据。
