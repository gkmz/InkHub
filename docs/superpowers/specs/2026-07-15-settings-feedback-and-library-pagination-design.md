# 设置反馈与内容库分页设计

## 目标与范围

本阶段解决三个已确认问题：设置页目录规则缺少当前状态摘要、未开发按钮点击无反馈、内容库只显示前 50 篇。文章类目设计不在本阶段修改。

## 目录规则摘要

`ContentScopePicker` 在目录搜索列表之前固定展示两组当前规则：

- “当前管理”：展示所有管理根目录及各自 Markdown 数量。
- “当前排除”：展示所有忽略目录；没有排除目录时显示明确空状态。

每个条目提供删除图标按钮，用户无需回到长列表中寻找勾选项。删除管理根目录时，同时移除该根目录下已经失效的排除项。搜索和勾选列表继续用于添加、查看候选目录和调整规则。

## 统一操作反馈

前端新增全局提示组件，提供 `info`、`success`、`error` 三类消息及明确的可访问状态。提示由统一 Hook 触发，自动消失，也允许用户主动关闭；同一时刻按触发顺序展示，避免操作结果被覆盖。

异步操作必须具备以下状态：

- 请求期间按钮显示进行中文案并阻止重复提交。
- 成功后展示 success 提示。
- 失败后展示服务端可理解错误或稳定的中文兜底消息。

尚未开发但界面已经出现的 AI 设置保存、发布设置保存和 Secret 删除操作保持可点击；点击后展示 info 提示，明确说明该功能尚未开放。相关控件不得伪装为已经持久化：AI 开关和模板选择可以展示当前配置，但本地修改不会显示“已保存”。

## 内容库稳定分页

后端使用基于“修改时间倒序、文章 ID 倒序”的 keyset cursor。cursor 为 URL 安全 Base64 编码的内部 JSON，包含上一页末项的排序时间和 ID；非法 cursor 返回分页参数错误。查询读取 `limit + 1` 条确定是否存在下一页，并只返回请求数量。

前端首次加载 50 条。存在 `next_cursor` 时在列表底部显示“加载更多”，点击后追加下一页并显示加载状态；搜索或审核筛选变化时清空旧列表和 cursor，从第一页重新查询。重复 ID 在追加时去重，避免数据更新造成重复展示。加载下一页失败时保留已加载文章并通过统一提示组件反馈。

## 边界与验收

- 目录摘要在搜索、滚动之前始终可见，并与勾选状态同步。
- 所有设置页按钮均有事件处理或真实表单行为；未开发功能点击后有明确提示。
- 50 篇以上文章可以持续加载至末页，末页不再显示加载按钮。
- cursor 不接受损坏、缺字段或过长值。
- 搜索与筛选的现有参数保持兼容；本阶段不扩展类目设计。
- 单元测试覆盖摘要删除、未开放提示、Toast 生命周期、分页首尾页、非法 cursor、前端追加与失败保留。
