# Hugo 手动标记同步成功设计

## 1. 目标

当 Hugo 同步任务失败，但用户已经在 InkHub 之外完成发布时，允许用户将当前文章版本的 Hugo 渠道手动标记为成功。该操作只记录外部发布事实、清除渠道失败投影并解除页面阻塞，不重新生成预览，也不写入 Hugo 文件。

## 2. 方案选择

采用现有文章处置接口 `POST /api/v1/articles/batch-disposition`，提交单篇文章、当前 `content_version`、`published` 操作和唯一渠道 `hugo`。现有后端已经提供文章版本校验、渠道校验、失败信息清理、Publication 更新和 `marked_published` 审计事件，因此不新增 Hugo 专用接口或第二套状态模型。

不采用仅在浏览器内跳过失败的方案，因为刷新页面后状态会丢失；不新增 Hugo 专用接口，因为它会重复现有处置服务的事务与校验逻辑。

## 3. 前端交互

`HugoPublishFlow` 只在当前版本的 Preview 或 Deliver 进入 `failed` 状态时展示“手动标记成功”次级按钮，并保留原有“重新生成预览”按钮，用户仍可选择正常重试。

点击按钮后打开确认对话框，文案明确说明：

> 仅记录当前版本已在外部完成发布，不会重新写入 Hugo 文件。

对话框提供“取消”和“确认标记”操作。提交期间禁止重复点击和关闭对话框。成功后显示成功提示，将当前页面切换为“当前版本已同步到 Hugo”，刷新文章详情和发布历史。失败时保留失败卡片与确认框，并展示服务端返回的可理解错误。

人工标记结果以文章详情中当前版本有效的 `disposition.channels` 包含 `hugo` 为依据。它的优先级高于旧的失败 Job：页面刷新后，旧 Job 仍留作诊断和历史事实，但不能把已经人工确认的当前版本重新显示为失败。普通 Hugo 同步成功仍沿用现有 Job 与真实文件系统校验，不受该优先级影响。

## 4. 数据流

1. Hugo 页面从文章详情判断当前内容版本是否已经人工标记为 Hugo 已发表。
2. 失败态点击“手动标记成功”，页面弹出确认对话框。
3. 确认后提交：

```json
{
  "operation": "published",
  "articles": [
    {
      "id": "<article_id>",
      "content_version": "<current_content_version>"
    }
  ],
  "channels": ["hugo"]
}
```

4. 后端在同一事务中把当前版本的 Hugo Publication 更新为 `published`，清除旧错误字段，并写入 `marked_published` 事件，其 payload 保持 `source=user`、`external=true`。
5. 页面重新读取文章详情和发布历史，通过新的人工发表处置进入成功终态。

## 5. 错误与边界

- 文章在确认前发生变化：现有版本校验返回 `409 disposition.content_changed`，页面提示内容已更新并要求刷新，不得标记旧版本。
- Hugo 渠道未配置或已停用：沿用 `disposition.channel_unavailable`，不伪造成功状态。
- 重复确认同一版本：接口保持幂等；前端提交期间禁用按钮。
- 内容后续发生变化：旧版本的人工标记不再对新版本生效，新版本重新进入正常 Hugo 发布流程。
- 旧失败 Job 和失败历史不删除，以保留诊断证据；新增的人工成功事件作为更新后的业务事实展示。
- 人工标记不会检查或创建本地 Hugo Bundle，因为用户已经确认文件由外部流程处理完成。

## 6. 代码范围

- `web/app/src/pages/hugo/HugoPage.tsx`：向 Hugo 流程传入当前版本的人工发表状态。
- `web/app/src/components/HugoPublishFlow.tsx`：增加失败态入口、确认对话框、提交逻辑和人工成功终态优先级。
- 前端样式文件：补充紧凑的失败态操作区和确认对话框样式，复用现有按钮与对话框视觉语言。
- `web/app/src/api/client.ts`：直接复用现有 `batchDisposition`，不新增 API。
- Go 后端与数据库：不修改，复用现有版本保护、事务、状态清理和审计事件。

## 7. 验证

按当前开发约束不新增测试代码。实现后执行前端类型检查和生产构建，并从页面人工验证：失败态入口、取消、确认成功、成功反馈、历史刷新、页面刷新后仍保持成功，以及文章内容变化后不沿用旧版本成功状态。
