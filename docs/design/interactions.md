# InkHub 交互设计

> 对应 PRD 1.4、架构设计 1.1，面向 MVP Release 1 的本地 Web UI。

## 1. 设计目标

InkHub 的界面服务于一个高频任务：从本地 Markdown 中找到需要处理的文章，完成审核，并可靠地交付到 Hugo 和微信公众号。

交互必须满足：

- 日常启动直接进入最近工作区，不重复要求路径和渠道。
- 页面一次突出一个主要任务，不展示无关能力。
- 用户不需要理解 Provider、content hash、数据库或任务队列。
- AI 建议、文件写回和渠道交付均由用户确认。
- 所有长任务有进度、取消或离开页面后的恢复入口。
- 键盘、窄屏、系统缩放和减少动态效果模式均可使用。

## 2. 视觉与布局方向

### 2.1 视觉语言

界面取意于编辑桌而不是 CMS 控制台：内容区域接近纸张阅读体验，工具区域像克制的校对边栏。页面不使用营销 hero、装饰性渐变、嵌套卡片或大面积单一色调。

基础 token：

| 角色 | 色值 | 用途 |
| --- | --- | --- |
| `paper` | `#FAFAF8` | 内容背景 |
| `surface` | `#FFFFFF` | 输入、菜单、弹层 |
| `ink` | `#202422` | 主文本 |
| `muted` | `#68706C` | 次要信息 |
| `action` | `#167C73` | 主要操作和焦点 |
| `warning` | `#B56A18` | 需要处理和过期 |
| `danger` | `#B33A3A` | 阻断与失败 |
| `line` | `#DDE1DE` | 分隔线和边界 |

正文与界面优先使用系统中文无衬线字体栈；文章预览尊重文章和渠道模板字体。数据、路径和代码使用系统等宽字体。字号使用固定 token，不随视口连续缩放；字间距为 `0`。

圆角不超过 6px，阴影只用于菜单和模态层。页面区块依靠分隔线、留白和固定栏宽组织，不包装成浮动卡片。

### 2.2 响应式框架

桌面宽度大于 1100px：左侧 216px 导航，中间弹性内容区，文章详情右侧 336px 工具栏。内容最大阅读宽度 760px。

```text
┌──────────────┬──────────────────────────┬──────────────────┐
│ 工作区/导航  │ 文章预览或列表           │ 审核与发布工具   │
│ 216px        │ minmax(0, 1fr)           │ 336px            │
└──────────────┴──────────────────────────┴──────────────────┘
```

769-1100px：导航折叠为 64px 图标栏，工具栏可收起为右侧抽屉。小于 769px：使用顶部栏和底部四项主导航；文章详情按“内容、审核、发布”三个标签切换，禁止横向溢出。

固定工具栏、计数和图标按钮必须有稳定尺寸。内容列表使用表格式行布局；移动端转为紧凑两行条目，不使用大卡片。

## 3. 信息架构与全局行为

主导航固定为：工作台、内容库、类目管理、设置。文章详情、任务、模板和历史记录是子页面，不增加主导航。

全局顶部区域只包含：当前工作区、页面标题、扫描状态和页面级操作。工作区切换使用菜单；任何路由跳转、浏览器返回、刷新或工作区切换遇到未保存表单时都必须确认。已提交但仍在运行的后台任务不阻止导航。

全局通知分三类：

- 页面内状态：与当前内容直接相关，持续显示。
- Toast：复制成功、设置保存等短暂结果，最多同时显示 3 条。
- 任务状态条：仅任务运行或失败时出现，可打开任务详情。

成功 Toast 4 秒后消失；错误不自动消失。刷新页面后，前端通过文章级工作流接口恢复当前内容版本的运行任务，不在浏览器保存或展示 job ID。

## 4. 首次初始化

初始化最多四步，顶部显示步骤名而非百分比。每一步只展示当前必须决定的内容，自动检测详情默认折叠。

### 4.1 第一步：选择内容库

字段：工作区名称、Obsidian Vault 路径。`选择目录` 由本地 Go 进程调用系统目录选择器，网页不依赖无法返回可靠绝对路径的目录上传控件；系统选择器不可用时允许手工输入路径。选择后立即校验 `.obsidian`、可读性和文件数量，结果在表单内显示。目录选择接口只接受同源请求，并在服务端重新执行路径授权和规范化。

主要按钮：`继续`。路径无效时按钮禁用，并显示可执行的修复说明。用户取消目录选择保持当前页面，不生成空工作区。

### 4.2 第二步：确认博客

展示检测到的 Hugo 根目录、内容 section、标准 taxonomy 配置和 Hugo CLI 状态。全部检测成功时显示一行摘要，详细路径折叠；未检测到时提供 `暂不配置博客`。

用户修改路径后重新验证。Hugo 配置或 taxonomy term 页面不可解析时允许跳过 Hugo，但不能以错误配置完成该步骤。

### 4.3 第三步：配置微信

默认选中 `InkHub Default`，并提供 Default/Minimal 的实际预览缩略图。图片托管配置可跳过；跳过后仍可预览无本地图片的内容，但准备含本地图片的文章时显示阻断。

Secret 输入只显示是否已保存，不回显值。测试连接失败不清空输入，允许修复或暂不启用。

### 4.4 第四步：可选 AI 与扫描

AI 默认关闭。启用后填写服务地址、模型、Secret 和隐私范围，并明确显示将发送“标题与元数据”“结构化摘录”或“全文”。

完成按钮为 `创建工作区`。创建成功后进入扫描页面：展示已发现文章数量、当前目录和可离开提示。扫描失败的单篇文章列入结果，不阻塞进入工作台。

初始化提交必须幂等；重复点击只创建一个工作区。浏览器关闭后再次打开，从最后已提交步骤恢复。

## 5. 工作台

工作台按处理优先级显示四个不嵌套的区段：

1. 需要审核。
2. 内容已更新。
3. 处理失败。
4. 最近处理。

每个区段是紧凑列表，行内展示标题、原因、修改时间、Hugo/微信自然语言状态和一个明确操作。没有待办时显示“目前没有需要处理的文章”，并提供 `浏览内容库`，不显示空统计卡。

排序：阻断失败最前，其次内容更新、元数据缺失、待审核，组内按最近修改时间降序。用户完成一项后，该行以 160ms 淡出并移动到最近处理；减少动态效果模式直接更新。

主要动作根据状态唯一决定：`补充信息`、`继续审核`、`查看更新` 或 `重试`。整行可进入文章详情，但行内按钮不得与整行点击产生冲突。

## 6. 内容库

顶部提供标题搜索和 `筛选` 按钮。桌面筛选栏包含目录、Category、Series、Tag、审核状态和渠道状态；移动端使用全屏筛选抽屉。已启用筛选以可移除条件显示，`清除筛选` 只在有条件时出现。

列表列为：标题、目录、Category、修改时间、审核、Hugo、微信。默认按修改时间降序，支持标题和修改时间排序。分页使用稳定 cursor；加载下一页不改变已有行位置。

搜索 300ms 防抖，输入法组合期间不触发。无结果时保留搜索和筛选，并说明“没有符合这些条件的文章”。扫描中允许浏览现有索引，列表顶部显示非阻塞状态。

## 7. 文章详情与审核

### 7.1 页面结构

桌面中间区域显示文章标题、来源相对路径和 Markdown 预览；右栏从上到下为发布轨道、元数据、检查结果、AI 建议和历史。

发布轨道是页面的识别性元素：

```text
审核        Hugo          微信
● 已通过 ── ○ 需要同步 ── ○ 尚未准备
```

轨道只使用自然语言状态和图标，不显示内部 hash。点击节点滚动到对应工具区。轨道不能代替操作按钮。

### 7.2 元数据编辑

字段：标题、Description、Category、Series、Tags、Keywords、Slug、Cover。Category 与 Series 使用当前博客 taxonomy 快照的单值下拉选择器；当前文章值不在快照时必须保留并标记“博客中未发现”，不能静默清空。未连接博客与临时读取失败使用不同提示，均不阻止编辑其他字段。Tags 使用独立的可创建多选器，不能直接复用单值选择器；支持搜索、键盘添加、删除，并展示快照中每个 Tag 的文章数量。

Category 与 Series 选择器旁只在 Provider 可写且存在 revision 时显示对应的新建按钮。新建流程复用 Taxonomy Provider 的 Hugo 原生文件预览和确认；创建成功只将新 term 回填到发起字段的文章表单草稿，用户仍需点击 `保存到文章` 才写回 Obsidian，禁止创建 term 时顺带隐式修改文章或串改另一个字段。

表单草稿保存在浏览器 session storage，以 workspace、article ID 和源文件指纹为 key，不包含正文或 Secret；关闭标签页后自动清除。只有点击 `保存到文章` 才写回 Markdown。保存前展示字段级变更摘要；若源文件指纹已变化，草稿标记失效，停止写回并提供 `重新加载`，不得覆盖外部编辑。

新 Tag 可以直接加入文章草稿，不单独创建 Hugo term page。文章发布到 Hugo 后，新 Tag 通过博客 frontmatter 进入权威来源，并在下一次 taxonomy 刷新时自然入库。AI 候选逐项采用或忽略，优先复用已有 Tag；AI 未配置或请求失败不影响手工编辑。

### 7.3 检查结果

按阻断、建议、可选、已通过分组；默认展开阻断和建议，折叠已通过。每项说明问题位置、影响渠道和修复动作。渠道特有问题只阻止对应渠道。

重新检查是后台任务。重复点击合并任务；检查期间保留上次结果并标注“正在重新检查”。

### 7.4 AI 建议

AI 未配置时不显示空面板或禁用的 AI 按钮，只在元数据区域提供 `配置 AI` 次要入口。已配置时由用户点击 `获取 AI 建议`。

建议按字段嵌入元数据编辑区，展示原值、建议值、简短原因以及 `采用`/`忽略`。可以逐项处理，不提供“全部覆盖”。建议对应旧内容版本时标记“文章已更新，请重新分析”，禁用采用。

AI 超时或输出无效时保留手工编辑，显示 `重试` 和简短原因，不弹全局模态框。

### 7.5 审核操作

只有元数据完整、稳定 ID 已写入且不存在通用阻断问题时，主要按钮为 `审核通过`。首次生成稳定 ID 前展示写回说明，与其他元数据在一次原子写入中完成。

从工作台进入元数据完整文章后，最多经过：打开文章、审核通过、选择渠道三次主要操作。审核完成后页面不跳转，发布轨道和主要动作更新为 `同步到 Hugo`；微信操作紧邻显示。

文章在审核期间被外部修改时，立即显示“文章已在写作工具中更新”，禁用审核和旧建议，重新读取后恢复。

历史记录默认折叠，展开后按时间倒序统一展示 Hugo 发布，以及微信准备、复制和人工确认。列表使用稳定 cursor 分页；每条只显示自然语言动作、安全结果摘要、时间和渠道。普通响应不返回内部 hash、job ID、数据库标识、原始任务结果或绝对路径。

## 8. 连续发布

### 8.1 Hugo

点击 `同步到 Hugo` 后展开内联流程。新文章先从 Hugo `content` 下已扫描到的一级目录中选择发布目录；只有一个候选时自动选择。已有文章按稳定 `source_id` 自动定位原目录，选择器只读，本阶段不允许跨目录移动，也不在 InkHub 中新增、重命名或删除目录。

用户点击 `生成发布预览` 后，后台依次执行 Preflight、Prepare 和隔离 staging Hugo build。预览完成后展示相对 Hugo 根目录的目标 bundle、增加或更新状态、文件相对路径、大小和检查结果。普通响应、页面和日志不得展示 Hugo root、staging 或 Artifact 的绝对路径。

只有 Ready 且未过期的预览显示 `确认同步到 Hugo`。确认时重新校验当前文章内容版本、工作区、Provider 和 staging manifest，并交付预览中保存的同一个 Artifact，禁止重新 Prepare 后静默交付另一份内容。内容变化、Artifact 过期或文件被修改时禁用确认并要求重新生成。

任务阶段显示：转换内容、复制资源、检查 taxonomy、构建预览、更新博客、最终确认。用户可离开页面、刷新浏览器或重启应用；返回文章后按当前工作区、文章、Provider 和内容版本恢复当前阶段。Deliver 优先于 Preview，旧内容版本的任务不得恢复到当前页面。进入原子替换后取消按钮禁用，并说明“正在完成文件更新”。

成功后显示 `打开预览` 和博客 URL。失败时保留原 bundle，显示失败步骤、摘要、`重试` 和日志入口，不将状态标为成功。

### 8.2 微信

点击 `准备微信内容` 后展示本次模板和将上传的本地图片清单。文章级临时切换模板不改变工作区默认值。

图片清单区分“将上传”和“已存在，直接复用”。只有用户点击 `确认并准备` 后才写入公开 GitHub 图片仓库；未配置、私有仓库、分支不存在、权限不足、图片缺失、越界、格式伪造、动画或尺寸超限均显示持久阻断反馈。页面只显示文章内相对引用，不显示 Vault 路径、摘要、Token 或任务 ID。

确认后执行准备任务，完成时进入最终预览。预览页顶部固定显示模板选择、`复制格式化内容` 和返回文章。最终剪贴板写入必须由用户点击直接触发，不能在后台任务完成后自动复制。复制成功记录“已复制”，按钮短暂变为 `已复制` 后恢复；剪贴板失败提供 `查看 HTML` 和下载兜底。

`草稿已保存` 是独立人工确认按钮，只在当前 content hash 已复制后出现。确认后记录时间和模板版本，不宣称已发布。文章更新后显示“微信草稿可能不是最新内容”。

### 8.3 多渠道顺序

审核完成后可以先处理任一已配置渠道。未配置的渠道不显示主要操作，只提供设置入口。一个渠道失败不影响另一个渠道；页面不提供含义模糊的“一键全平台发布”。完成 Hugo 后，页面保持当前位置并突出下一项 `准备微信内容`。

## 9. 类目管理

页面打开后立即展示 SQLite 中最近一次成功的 taxonomy 快照，顶部显示博客来源、同步状态和最后加载时间。用户可手工刷新；刷新失败时保留旧快照并显示可执行的错误信息。未配置博客时显示设置引导，而不是空白页面或无效按钮。

默认视图展示 Hugo categories，支持按名称和标识搜索，并显示文章使用次数；series 和 tags 通过同页分段控件切换为只读列表。可写 Provider 在类目视图提供 `新建类目`，用户只填写名称和说明，不需要理解路径或 frontmatter key。

新增类目必须先调用 Taxonomy Provider 生成 Hugo 原生 term page 变更，展示目标相对路径和文件内容后再确认。确认时服务端基于同一 revision 重新规划，禁止客户端提交任意文件路径或内容；revision 冲突时保留表单并提示刷新后重试。写入成功后更新 SQLite 快照和页面列表。只读 Provider 仍可浏览和刷新，但不显示创建入口。

## 10. 模板浏览与选择

设置中的模板列表采用紧凑双列缩略图，卡片只用于重复模板项，不嵌套其他卡片。每项显示实际 preview.png、名称、作者、版本、兼容性和安装状态。

模板详情提供大图预览、变量设置、`试用预览`、安装/更新和设为默认。安装前显示来源、许可证和包大小；自定义索引明确标识来源。更新失败继续使用旧版本，并提供错误摘要。

文章发布时临时选模板使用菜单和并排预览，不修改默认设置。默认模板被禁用或不兼容时自动回退 Default，并在设置页显示持续提示。

## 11. 设置与诊断

设置仅四组：工作区、AI、发布渠道、数据与诊断。每组是全宽区段，常用项直接显示，高级项使用可访问的 disclosure 展开。

保存采用分组提交，不提供会误导用户的全页保存。路径或 Provider 改动需要重建实例时，保存后显示重新验证状态。Secret 字段支持替换和删除，不显示原值。

Doctor 结果只使用“正常、需要处理、未启用”。每个问题包含原因、修复动作和重试；诊断包导出前列出包含内容，并明确不含正文和 Secret。

## 12. 异常、并发与恢复

- 重复点击：按钮在请求确认后进入稳定 loading 状态，服务端同时使用幂等键。
- 重复预览或确认：相同文章、Provider、内容版本和 Section 返回同一确定性任务，包括任务已经成功的情况。
- 页面刷新：表单草稿恢复；运行任务通过文章级工作流恢复；Ready 预览可继续确认，模态确认不自动恢复。
- 用户取消：可取消阶段停止并清理 staging；原子文件阶段完成后再返回结果。
- 内容变化：旧 AI 建议、审核和发布预览失效，不允许继续交付。
- 文件删除：详情转为只读，保留发布历史，提供从内容库移除索引的确认操作。
- 路径失效：保留工作区和历史，主操作改为 `修复路径`。
- 离线：本地浏览和编辑可用；AI、模板下载和图片上传显示不可用，不循环弹错。
- 服务重启：恢复可重试任务；不能安全恢复的任务显示失败和下一步。

所有破坏性操作使用明确对象和结果的确认文案，例如“从 12 篇文章中合并 Tag”，不使用模糊的“确定吗”。

## 13. 可访问性与输入

- 所有功能可通过键盘完成，焦点顺序与视觉顺序一致。
- 可见焦点环使用 action 色并满足 3:1 对比；正文文本满足 WCAG AA。
- 图标按钮有可访问名称和 tooltip；状态不只依赖颜色。
- 模态框锁定焦点，关闭后返回触发控件；Escape 不关闭正在执行不可逆操作的确认层。
- 表单错误与字段关联，提交失败后聚焦第一处错误。
- 尊重 `prefers-reduced-motion`；无自动播放动画和闪烁。
- 200% 系统缩放和 320px 宽度下不遮挡操作或产生页面横向滚动。

## 14. 关键验收流程

1. 新用户在四步内创建工作区，可跳过 Hugo、微信图片托管和 AI。
2. 元数据完整文章从工作台到审核通过不超过三次主要操作。
3. AI 不可用时可手工完成全部审核。
4. Hugo 失败后原内容不变，界面不显示成功。
5. 微信准备、复制、草稿确认是三个可区分状态。
6. 文章更新后审核和对应渠道明确显示需要重新处理。
7. 新类目或 Tag 写入前展示 Provider 生成的原生文件 diff；外部 revision 变化时拒绝覆盖并提示刷新。
8. Default、Minimal 和第三方模板使用相同选择与预览流程。
9. 页面刷新、浏览器返回和服务重启不会丢失已提交状态。
10. 桌面、平板和移动布局均无文字遮挡、工具重叠或不可达操作。
